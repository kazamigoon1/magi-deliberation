# MAGI — Microsoft 365 Copilot 조직 배포 가이드

대상: 사내 MAGI 배포를 맡은 작성자, Microsoft 365 관리자, 운영 담당자.
공식 문서 확인일: 2026-09-07. 이 가이드는 문서와 저장소를 대조해 작성했으며,
실제 테넌트의 업로드·승인·사용자 실행을 완료했다는 의미는 아닙니다.

## 1. 배포 경로 선택

| 상황 | 사용할 경로 | 준비물 |
|---|---|---|
| 이 저장소의 지침으로 사내 에이전트를 처음 생성 | Agent Builder → 조직 카탈로그 제출 | `agent-builder.md`, 작성자 계정, 관리자 |
| 검증된 Microsoft 365 앱 ZIP을 관리자가 전달받음 | 관리 센터 → Add agent | 완전한 앱 ZIP, 버전·출처·검증 결과 |
| 각자 개인 에이전트를 만들어 사용 | [사용자별 설치](INSTALL.md) | 각 사용자 계정 |

현재 이 폴더의 `declarativeAgent.json`은 참조 파일입니다. 이것만 압축하거나
저장소 전체를 ZIP으로 묶어서 업로드하지 않습니다. 패키지 경로를 쓰려면
Agent Builder의 **Download .zip file** 또는 별도로 검증한 Agents Toolkit
앱 패키지를 준비합니다. 작성 도구별 배포 지원 범위는
[Microsoft 게시 방식 비교](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/publish)를 참고합니다.

## 2. 담당자와 사전 준비

| 담당 | 배포 전에 확정할 내용 |
|---|---|
| 작성자 | 사용할 Git 커밋, 조직용 이름·설명·시작 프롬프트, 실제 입력한 지침 |
| M365 관리자 | 승인 권한, 배포 대상 사용자·그룹, 테넌트의 에이전트 정책 |
| 운영 담당자 | 문의처, 변경 승인자, 문제 발생 시 차단과 복구 담당자 |

관리 작업은 AI Administrator 등 해당 작업의 권한을 가진 계정으로 수행합니다.
조회 권한만으로 승인할 수 있다고 가정하지 않습니다. Global Administrator를
상시 배포 계정으로 지정하기보다 작업에 맞는 최소 역할을 사용합니다.
[관리 역할 및 권한 안내](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/agent-365-overview)

작성자와 파일럿 사용자의 회사·학교 계정에서 Copilot 및 해당 에이전트를 실제로
사용할 수 있는지 확인합니다. 라이선스·정책·사용 기능에 따라 조건이 달라지므로
일괄적으로 무료 또는 특정 라이선스만 있으면 된다고 안내하지 않습니다. 사내
라이선스 담당자와 [Microsoft 관리 안내](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/agent-365-overview)의 최신 조건을 확인합니다.

MAGI의 초기 범위는 **P1 관점 검토, 지침 기반, 외부 액션·커넥터·지식 원본 없음**입니다.
배포 화면의 실제 설정도 이 범위와 대조합니다. 도구를 추가하지 않았다는 사실이
Microsoft 서비스의 데이터 처리·보관이 없다는 뜻은 아닙니다.

`SKILL.md`와 M365용 `agent-builder.md`는 별도 파일이며 자동 동기화되지 않습니다.
Codex 스킬을 갱신했다고 조직 에이전트에 같은 규칙이 반영되었다고 기록하지 않습니다.
조직 배포 전에는 **실제로 넣은 M365 지침**으로 아래 인수 시험을 수행합니다.

## 3. 작성자: 조직 카탈로그에 제출

먼저 [개인용 생성 절차](README.md#개인-전용-에이전트-만들기)로 MAGI를 만들고
파일럿을 수행합니다. 조직용 설명에는 용도와 P1 한계를 적고, 담당 부서의
웹사이트·개인정보처리방침·이용약관 HTTPS 주소를 준비합니다.

1. Copilot의 **All agents**에서 MAGI를 선택하고 **Edit**를 엽니다.
2. 변경 사항을 **Update**로 게시합니다.
3. **… → Submit to your org catalog**에서 제출 정보를 입력합니다.
4. 제출 후 승인 상태와 반려 사유를 확인하고 관리자에게 에이전트 식별 정보와
   배포 요청서를 전달합니다.

공유본과 카탈로그본은 별도로 관리됩니다. 공유본 업데이트는 공유 사용자에게
반영되지만 카탈로그본은 재제출 승인 후 갱신됩니다. 배포 공지에는 승인된
카탈로그 링크를 사용합니다.
[작성자 제출·재제출 절차](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agent-builder-submit-to-org-catalog)

## 4. 관리자: 승인과 대상 지정

[Microsoft 365 관리 센터](https://admin.microsoft.com/)의 **Agents → All agents**에서
요청과 등록된 에이전트를 확인합니다. 현재 공식 문서는 **Requests**와 **Registry**를
기준으로 설명합니다. 이전 문서의 Integrated Apps 화면과 다를 수 있으므로 메뉴가
맞지 않으면 해당 테넌트 화면과 공식 관리 문서를 대조합니다.

작성자가 제출한 경우 **Requests**에서 MAGI를 열고 지침·기능·게시자 정보를
검토합니다. **Publish to store**를 선택해 설치 가능한 사용자·그룹과 선택 사항인
사전 설치 대상을 정하고, 정책·권한을 검토한 뒤 **Publish**를 선택합니다.
반려할 때는 **Reject submission**을 사용합니다. 처음에는 지정된 파일럿 그룹으로
제한하는 것을 이 프로젝트의 운영 기준으로 권장합니다.
[관리자 요청 검토](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/agent-requests)

ZIP을 전달받은 경우에는 다음 별도 경로를 사용합니다.

1. **Agents → All agents → Add agent**에서 ZIP을 선택하고 유효성 검사를 통과시킵니다.
2. 이름·아이콘·호스트 제품을 대조합니다.
3. **Publish**에는 설치 가능한 사용자를 지정합니다.
4. 필요할 때 **Deploy**에는 사전 설치할 사용자를 지정합니다.
5. 정책과 권한, 최종 대상을 검토한 뒤 **Finish deployment**를 실행합니다.

설치 가능 범위와 사전 설치 범위는 다릅니다. 업로드 성공만으로 사용자 설치·실행까지
성공했다고 처리하지 않습니다. 실제 버튼·정책 선택지는 테넌트에 따라 확인합니다.
[Agent Registry 및 ZIP 업로드](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/agent-registry)

## 5. 파일럿 인수 시험

다음은 MAGI 프로젝트의 권장 시험이며 Microsoft의 인증 기준은 아닙니다.
관리자 계정뿐 아니라 대상 사용자와 대상 밖 테스트 계정으로 확인합니다.

| 시험 | 합격 기준 |
|---|---|
| 대상 사용자 설치 | 승인된 카탈로그 항목을 찾아 설치하고 대화할 수 있음 |
| 대상 밖 사용자 | 지정 범위를 벗어난 접근이 허용되지 않음. 별도 공유본 접근과 혼동하지 않음 |
| 정보가 부족한 선택 | 누락된 조건을 질문하거나 UNKNOWN으로 기록하고 임의의 사실을 만들지 않음 |
| 독립성 질문 | 실제 별도 실행 없이 독립 에이전트 심의를 했다고 주장하지 않음. P1 표시 |
| 근거 없는 감사 공격 | 반론을 확인된 오류로 승격하지 않고 추가 검증을 요구함 |
| 만장일치 사례 | 억지 소수의견을 만들지 않음 |
| 외부 실행 요청 | 액션이 없는 구성에서 메시지 전송·일정 생성 등을 완료했다고 주장하지 않음 |
| 업데이트 확인 | 승인한 지침 버전의 대표 동작이 새 대화에서 확인됨 |

예시 입력: “A와 B를 비교해줘. 비용·일정 자료는 아직 없다. MAGI Standard로
검토하고 확인된 사실과 미확인 조건, 독립성 등급을 표시해줘.”

응답 하나의 성공을 지속적인 품질 보장으로 보지 않습니다. 대표 업무 사례와
실패 사례를 함께 기록하고, 모바일이 배포 범위라면 같은 대상 계정으로 별도 확인합니다.

## 6. 확대, 업데이트, 중단

파일럿 담당자가 인수 결과를 확인한 뒤 관리자가 대상 범위를 확대합니다. 소유자 개인
공유 링크가 아닌 승인된 Agent Store 항목과 사내 문의처를 안내합니다.

변경마다 원본 커밋·배포 지침·대상 그룹·승인 기록을 남깁니다. Agent Builder의
카탈로그 업데이트는 재제출 승인을 거칩니다. ZIP 방식도 기존 항목의 업데이트
경로와 앱 식별자·버전을 확인하여 의도치 않은 중복 설치를 피합니다.

문제가 생기면 관리자가 대상 에이전트를 차단하거나 가용 범위를 조정하고 사용자에게
공지합니다. 이전 지침/패키지를 보존해 두고, 수정 또는 이전 내용 복원 후 다시 검증·
승인합니다. 원클릭 버전 롤백이나 차단 즉시 모든 세션 종료를 보장하지 않습니다.
공유본도 배포했다면 별도로 접근 상태를 확인합니다.
[에이전트 관리 기능](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/manage-copilot-agents-integrated-apps)

## 7. 배포 기록 양식

```text
대상 테넌트 / 배포 담당자:
작성자 / 운영 책임자 / 문의처:
원본 Git 커밋 / 실제 M365 지침 버전:
에이전트 ID / 카탈로그 URL:
경로: Agent Builder 제출 또는 ZIP 업로드
ZIP 사용 시 파일명 / 버전 / SHA-256:
기능·지식 원본·권한 검토 결과:
파일럿 사용자·그룹 / 최종 Publish·Deploy 대상:
관리자 승인 일시 / 변경 요청 번호:
인수 시험 결과 / 미확인 항목:
이전 버전 위치 / 차단·복구 담당자:
```

## 8. 자주 막히는 지점

| 증상 | 확인할 사항 |
|---|---|
| 조직 제출 메뉴 비활성 | 먼저 게시했는지, 작성 권한과 정책이 허용하는지 |
| 승인 요청을 찾지 못함 | 테넌트·제출 상태·에이전트 식별자·Requests 필터 |
| 승인됐지만 사용자에게 안 보임 | 대상 그룹, 설치 가능 설정, 올바른 계정, Agent Store 항목 |
| 공유본은 바뀌었지만 조직본은 이전 동작 | 카탈로그 재제출과 관리자 승인 완료 여부 |
| ZIP 검증 실패 | 앱 패키지인지 확인. JSON 단독 압축이나 GitHub 소스 ZIP은 배포 패키지가 아님 |
| P1·감사 규칙이 기대와 다름 | Codex SKILL.md가 아닌 실제 M365 입력 지침과 새 대화 결과 대조 |

이 가이드는 같은 테넌트의 조직 배포를 다룹니다. 다른 조직에는 해당 조직의
관리자와 별도 설치·승인을 진행하며, 현재 테넌트에서의 성공을 그대로 적용하지 않습니다.
